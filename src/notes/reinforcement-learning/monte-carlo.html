A robot lives in a small home with a kitchen, a hallway, a study and a charger. It wanders. From the kitchen it always goes to the hallway. From the hallway it picks the study or the kitchen at random, and from the study, the charger or back to the hallway. Every move costs 1, and a trip ends at the charger.

How good is each room, that is, how many moves will the trip take from there? The robot cannot work it out, since it does not know the layout. But it can find out from experience. Each time it reaches the charger, it knows how many moves the trip actually took from every room it passed through, and averaging those numbers over many trips gives the answer.

That is a Monte Carlo method: estimate values by averaging what actually happened in complete episodes. This note does it first for a fixed way of behaving, then for the value of each action, and then uses those values to behave better. Along the way it runs into the one thing Monte Carlo methods cannot do without: continuing to try every action.

Throughout this page, the robot's moves are drawn in blue ink.

1Averaging returns

A policy π says how the agent chooses actions, here the robot's random moves. The value of a state under π is the return to expect from it, the sum of the rewards until the episode ends at time T, discounted by γ:

vπ(s) = Eπ[Gt | St = s], Gt = Rt+1 + γRt+2 + ⋯ + γT−t−1RT

An expected value can be estimated by an average of samples, and each visit to s in an episode gives one sample: the return that followed it. A state can be visited more than once in the same episode. First-visit Monte Carlo averages only the returns after the first visit to s in each episode; every-visit Monte Carlo averages the returns after all visits.

In the home γ = 1 and every move gives −1, so a return is minus the number of moves left. Here are two trips:

TripRooms, in orderReturns from each
1kitchen, hallway, study−3, −2, −1
2kitchen, hallway, kitchen, hallway, study, hallway, study−7, −6, −5, −4, −3, −2, −1

In the second trip the robot starts in the kitchen with 7 moves ahead, returns to the kitchen with 5 left, and so on. First-visit Monte Carlo takes, from each trip, the return after a room's first visit: −3 and −7 for the kitchen, which average −5. Every-visit Monte Carlo also takes the −5 of the second visit, and (−3 − 7 − 5)/3 is −5 too. They differ for the hallway: every-visit averages four returns, (−2 − 6 − 4 − 2)/4 = −3.5, and first-visit two, (−2 − 6)/2 = −4.

kitchen−5−5−9
hallway−4−3.5−8

Two short trips are a poor sample: the true values are much lower, since many trips go back and forth for a while. They follow from the relations between neighboring rooms: the study's value is the average of its two moves, v(study) = ½(−1) + ½(−1 + v(hallway)), and likewise for the other rooms, which gives −9, −8 and −5. Averaging more trips gets there: after 10,000 trips, both methods are within 0.1 of these values.

Both methods converge to vπ(s) as the number of visits grows. For first-visit Monte Carlo this is the law of large numbers: each return is an independent sample whose expectation is vπ(s), so the average is unbiased, and its error shrinks like 1/√n after n returns. Every-visit Monte Carlo converges too, though its samples from the same episode are not independent.

The algorithm

Returns are easiest to compute backward from the end of the episode, since Gt = Rt+1 + γGt+1. First-visit Monte Carlo prediction, for a policy π:

  1. Start with any estimates V(s) and an empty list of returns for each state.
  2. Generate an episode by following π: S0, A0, R1, …, ST−1, AT−1, RT. Set G ← 0.
  3. For t = T − 1, T − 2, …, 0: set G ← γG + Rt+1. If St does not appear earlier in the episode, add G to the returns of St and set V(St) to their average.
  4. Repeat from step 2 for each new episode. Every-visit Monte Carlo is the same without the check of step 3.

Averaging as you go

There is no need to keep every return. After a new return Gt, the average of the N(St) returns seen so far moves toward it:

V(St) ← V(St) + 1N(St)[Gt − V(St)]

For the hallway, the first return, −2, gives V = −2, and the second, −6, gives −2 + ½(−6 + 2) = −4, the same average as before. A constant step size α in place of 1/N gives constant-α Monte Carlo, V(St) ← V(St) + α[Gt − V(St)], which weights recent returns more. That suits problems that change over time, such as learning about a policy that keeps changing.

No bootstrapping

Each estimate comes from its own returns only: the estimate for the kitchen does not use the estimate for the hallway. Monte Carlo methods do not bootstrap, that is, they do not build estimates on other estimates. A consequence is that estimating one state costs the same however many states there are, so a Monte Carlo method can study a few states of interest by starting many episodes from them and ignoring the rest. The price is waiting: an estimate changes only when its episode ends.

2Values of actions

State values are enough to choose actions only with a model of the world: knowing that a move from the hallway leads to the study, the robot could compare the rooms each move leads to. Without a model it needs the value of each action directly:

qπ(s, a) = Eπ[Gt | St = s, At = a]

the return to expect after taking action a in state s and following π afterward. Monte Carlo estimates it the same way, by averaging the returns after visits to the pair (s, a), first visits or all visits. For the wandering robot, going from the study to the charger is worth −1, and going back to the hallway −1 + (−8) = −9; going from the hallway to the study is worth −6, and back to the kitchen −10.

The complication is that many pairs may never be visited. If the robot always went from the study straight to the charger, it would never see a return for going back to the hallway, and could never learn whether that move is better or worse. To compare actions, every pair has to keep being tried. One way to guarantee it is exploring starts: each episode starts from a state–action pair chosen at random, with every pair having some chance. That is easy in a simulation and usually impossible in the real world, where episodes start wherever they start.

3Improving the policy

With action values, a better policy is easy to find: in each state, take the action with the largest value. A policy that does that with respect to q is greedy:

π(s) ≐ argmaxa q(s, a)

The greedy policy is at least as good as π everywhere. Following it for one step and π afterward is worth maxa qπ(s, a), which is at least vπ(s), the value of following π all along; by the policy improvement theorem, following it every step is at least as good too. In the home, the greedy policy with respect to the values above goes from the hallway to the study (−6 beats −10) and from the study to the charger (−1 beats −9). That is the best policy, with values −3, −2 and −1.

Control alternates the two steps: evaluate the current policy, make the policy greedy with respect to the evaluation, and repeat. Each step moves toward what the other needs, and when neither changes anything, both the policy and its values are optimal. This pattern is called generalized policy iteration (GPI). Evaluation need not be complete: Monte Carlo methods alternate after every episode, updating the values of the pairs visited and then the policy at those states.

Monte Carlo with Exploring Starts, Monte Carlo ES, does exactly that. It starts each episode from a random pair and then follows the current greedy policy; after the episode, it averages each visited pair's first-visit return into Q and makes the policy greedy in the states visited. It cannot settle on a policy that is not optimal: the values would converge to that policy's values, and the greedy step would then change it. That it always converges to the optimum is widely believed but has not been formally proved.

4Control without exploring starts

Without exploring starts, the only way to keep trying every action is for the policy itself to keep choosing them. There are two ways to do that. On-policy methods evaluate and improve the same policy that makes the decisions. Off-policy methods evaluate or improve a policy different from the one that generates the experience. This section is about an on-policy method.

The policy is kept soft, with π(a|s) > 0 for every action. An ε-soft policy gives every action at least ε/|𝒜(s)|, where |𝒜(s)| is the number of actions in s. The closest of them to greedy is ε-greedy: it gives each non-greedy action exactly ε/|𝒜(s)| and the greedy action the rest, 1 − ε + ε/|𝒜(s)|. On-policy first-visit Monte Carlo control is Monte Carlo ES with one change: episodes start however they start, and the improvement step makes the policy ε-greedy with respect to Q instead of greedy.

The algorithm

On-policy first-visit Monte Carlo control, for a small ε > 0:

  1. Start with any Q(s, a), an empty list of returns for each pair, and π ε-greedy with respect to Q.
  2. Generate an episode by following π: S0, A0, R1, …, ST−1, AT−1, RT. Set G ← 0.
  3. For t = T − 1, T − 2, …, 0: set G ← γG + Rt+1. If the pair St, At does not appear earlier in the episode, add G to its returns, set Q(St, At) to their average, and make π ε-greedy in St with respect to Q.
  4. Repeat from step 2 for each new episode.

The ε-greedy step still improves the policy. For any ε-soft π, the ε-greedy policy π′ with respect to qπ satisfies, in every state,

Σa π′(a|s) qπ(s, a) ≥ vπ(s)

because π′ puts its extra weight on the largest qπ(s, a), and a weighted average never exceeds its largest term. By the policy improvement theorem, π′ is at least as good as π. In the study, with ε = 0.2 and two actions, π′ goes to the charger with probability 0.9: 0.9(−1) + 0.1(−9) = −1.8, well above the wandering robot's −5.

Where does it end? The process stops improving only at the best ε-soft policy, which is not the best policy: it keeps exploring forever, and exploring costs something. In the home, the ε-greedy policy with ε = 0.2 around the best moves has values −3.47, −2.47 and −1.25, against −3, −2 and −1 without exploration. Letting ε shrink over time closes that gap.
