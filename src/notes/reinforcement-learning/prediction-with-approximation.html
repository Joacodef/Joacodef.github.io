Every method in the earlier notes keeps a table, with one estimate for each state, or for each state and action, and learns each entry only from visits to its own state. That works in small worlds such as the nine cells of the cookie grid. It fails when an agent cannot hope to visit every state, let alone visit each one often.

Take a cart that rolls along a track, carrying a pole on a hinge. At every step the agent pushes the cart left or right, and it earns +1 for each step the pole stays up; an episode ends when the pole leans past 12° or the cart leaves the track. The state is four numbers: where the cart is and how fast it moves, the pole's angle and how fast it turns. Measured finely, they almost never repeat, so a table would hold one entry for each state ever visited, each updated once, and nothing for the next state, which is new.

The way out is to stop learning each state on its own. A few numbers describe each state, such as the pole's angle, and a few weights, shared by all the states, turn those numbers into a value. Learning adjusts the weights, so whatever one state teaches carries over to every state described by similar numbers, including states never visited.

The price is that no set of weights can fit every state, so the agent has to decide which errors to accept. Monte Carlo and TD both carry over, but they no longer settle on the same answer, even with endless experience. This note is about prediction, estimating the values of a fixed policy: here, how long the pole stays up while the cart is pushed at random, before any agent learns to keep it up.

Throughout this page, the estimates, the bars the weights set, are drawn in blue ink, and what they aim for, the true values or the target of an update, in red ink.

1Values from weights

The eligibility traces note wrote its updates for any estimate v(s, w), the value of state s given a vector of weights w, with a table as the simplest case, one weight per state. From here on, the weights are far fewer than the states. Each state is described by a feature vector, d numbers computed from the state:

x(s) ≐ (x1(s), x2(s), …, xd(s))T

and the simplest estimate, the one this note uses, is linear in the weights: each feature times its weight, added up.

v(s, w) ≐ wTx(s) ≐ Σdi=1wixi(s)

For the cart-pole, the features could be the four numbers of the state, or anything computed from them. This note's agent keeps just one thing: the pole's angle, cut into six ranges of 4° from −12° to 12°. Each range is a feature, 1 when the pole leans within it and 0 otherwise, so d = 6, and v(s, w) is simply the weight of the range the pole is in. This is state aggregation: the states of a range share one weight, and so one value.

A table is linear too, with one feature per state, 1 in its own state and 0 in every other. Choosing features is choosing what the agent can tell apart: this agent cannot tell a pole swinging back toward upright from one falling over, if they lean the same. The gain is that every state gets a value, even one never seen, as long as its features can be computed. The price is that an update no longer stays where it is made: changing a weight to correct one state's estimate changes the estimate of every state with that feature, here every state in its range.

Each update of the earlier notes moved the estimate of a state St toward a target: the return Gt in Monte Carlo, Rt+1 + γv(St+1, w) in TD(0), the n-step return Gt:t+n in n-step TD. Each such pair, the state's features and its target, is now an example for supervised learning, which fits a function to examples of inputs and the outputs wanted for them. Any supervised method could adjust the weights, as long as it learns from examples that arrive one at a time, as the agent moves, and copes with targets that change as the estimates improve. This note uses the simplest, gradient descent.

2Which errors matter

With fewer weights than states, the estimates cannot all be right, and making one better can make others worse. To choose among them, weigh each state's squared error by how much that state matters, with a distribution μ(s) ≥ 0, Σs μ(s) = 1. The result is the mean squared value error:

VE(w) ≐ Σs∈𝒮 μ(s)[vπ(s) − v(s, w)]2

Its square root gives a rough idea of how far the estimates are from the true values. The usual μ is the fraction of time the policy spends in each state, called the on-policy distribution: the states the agent visits most are the ones whose estimates it uses most. In an episodic task it follows from two quantities: h(s), the probability that an episode starts in s, and η(s), the number of steps an episode spends in s on average. Time is spent in s when an episode starts there, or when a step leads there from a state where time is spent:

η(s) = h(s) + Σs̄ η(s̄) Σa π(a|s̄)p(s|s̄, a), μ(s) = η(s)Σs′ η(s′)

With discounting, a factor γ in the second term treats it as a chance that the episode ends. Pushed at random, the pole spends 29% of its time in each of the two middle ranges, 12% in each range from 4° to 8°, and 8% in each outer one. Inside a range the true values differ: a pole between 4° and 8° that is swinging back toward upright can stay up 20 more steps or more, and one falling away only 2 or 3. One weight cannot match them all, and VE weighs each miss by how often its state comes. VE is least with each bar at the average of its range's states, weighed by how often they come: about 19 steps in the middle ranges, 12 from 4° to 8°, and 5 past 8°. What remains, 22.8, a typical miss of 4.8 steps, is the spread inside the ranges, which only better features could reduce. In practice nobody computes μ: following π brings each state at these rates, so learning from the states as they come weighs their errors by μ. A linear estimate has a single minimum of VE; an estimate that is not linear in its weights, such as a neural network, can have many, and the methods below may then find only one near where they start. Nor is VE certain to be the right goal: values are wanted for choosing actions, and the values with the least VE are not necessarily the best for that. It is the goal this note uses.

3Learning from returns

Suppose for a moment that each visit to a state St came with its true value. The weights could then take a small step in the direction that reduces that state's squared error fastest, against its gradient:

wt+1 ≐ wt − ½α∇[vπ(St) − v(St, wt)]2
= wt + α[vπ(St) − v(St, wt)] ∇v(St, wt)

The gradient ∇v is the vector of the estimate's partial derivatives with respect to the weights. It says which weights produced the estimate of St, and how much, and for a linear estimate it is simply the feature vector, ∇v(s, w) = x(s). The method is stochastic gradient descent: each step looks at one state, the one just visited, and may make other states' errors worse. States come at the rates μ sets, so over many small steps the weights go down VE. The steps must stay small, since steps that removed each state's error completely would just chase the last state visited. With a step size that shrinks over time at the right rate, the weights converge to a minimum of VE, or to one of its minima if it has several.

The true value is unknown, so the update uses a target Ut in its place:

wt+1 ≐ wt + α[Ut − v(St, wt)] ∇v(St, wt)

If the target is right on average, E[Ut | St = s] = vπ(s), the guarantee stays the same. The return is right on average by definition, since vπ(s) is the return to expect from s. With Ut = Gt, the update is gradient Monte Carlo.

The algorithm

Gradient Monte Carlo, for a policy π, an estimate v differentiable in its weights, and a step size α > 0:

  1. Start with any weights w, for example all 0.
  2. Generate an episode S0, A0, R1, …, ST−1, AT−1, RT following π.
  3. For each step, t = 0, 1, …, T − 1, update w ← w + α[Gt − v(St, w)] ∇v(St, w).
  4. Go back to step 2 for the next episode.

With state aggregation, ∇v is 1 for the weight of St's range and 0 for the others, so each update moves one weight, the shared estimate of a whole range, toward the return of one of its states.

4Learning from the next estimate

TD(0) uses the target Ut = Rt+1 + γv(St+1, wt), built from the weights themselves, and that has two consequences. First, the target is right on average only if the next state's estimate is, so it is biased, and the guarantee of the last section no longer applies. Second, the step of the last section is the gradient of the squared error only for a target that does not depend on the weights. This one does: changing the weights changes the next state's estimate, and with it the target. The update takes into account how the weights move the estimate of St, and ignores how they move the target. It follows only part of the gradient, so it is called a semi-gradient method:

wt+1 ≐ wt + α[Rt+1 + γv(St+1, wt) − v(St, wt)] ∇v(St, wt)

In the cart-pole, 85% of the steps leave the pole in the range it was in. The target of such a step is the reward, 1, plus the very weight being updated, so the TD error is 1 whatever that weight is, and the update raises the estimate and the target together: it chases a target that moves with it.

Why use it, then? For the reasons of the TD note: it learns from every step without waiting for the end of an episode, it works in tasks that never end, and its targets vary less than returns, so it usually learns faster. And with a linear estimate it converges reliably, to a point that the next section finds.

The algorithm

Semi-gradient TD(0), for a policy π, an estimate v differentiable in its weights with v(terminal, ·) = 0, and a step size α > 0:

  1. Start with any weights w, for example all 0.
  2. At the start of each episode, observe the first state S.
  3. Take the action π gives for S, and observe the reward R and the next state S′.
  4. Update w ← w + α[R + γv(S′, w) − v(S, w)] ∇v(S, w).
  5. Set S ← S′, and go back to step 3 until S is terminal.

5Where each method settles

With a linear estimate the gradient is the feature vector, so the general update becomes

wt+1 ≐ wt + α[Ut − v(St, wt)] x(St)

and each weight moves in proportion to its own feature. A linear VE has a single minimum, or, when some features merely repeat others, a set of equally good ones. So gradient Monte Carlo, with a step size that shrinks appropriately, converges to the weights with the least VE: in the cart-pole, each range's average, 18.9 steps in the middle ranges, 11.8 from 4° to 8°, and 4.8 past 8°.

Semi-gradient TD(0) converges too, though not by the same argument, and not to the same weights. Writing xt for x(St), its update is

wt+1 ≐ wt + α(Rt+1 + γwTtxt+1 − wTtxt)xt
= wt + α(Rt+1xt − xt(xt − γxt+1)Twt)

Averaged over the states the policy visits and the steps it takes from them, the next weights are

E[wt+1 | wt] = wt + α(b − Awt),
b ≐ E[Rt+1xt], A ≐ E[xt(xt − γxt+1)T]

so on average the weights stop moving where b − Aw = 0:

wTD ≐ A−1b

This is the TD fixed point, and linear semi-gradient TD(0) converges to it. With state aggregation it has a plain meaning: each range's weight equals the average, over the steps taken from that range, of the reward plus the weight of the range the step lands in (0 after a fall). TD treats the ranges as if they were the states. They are not: between 4° and 8°, some poles are swinging back toward upright and some are falling, and the range of the next step depends on which. TD borrows the same average for both, and settles at 22.3 steps in the middle ranges, 3.4 above their averages, and at 10.7 and 3.9 farther out, about 1 below. Its VE is 29.9, against the least, 22.8.

How far off can TD's fixed point be? For continuing tasks with γ < 1, it has been proved that

VE(wTD) ≤ 11 − γ minw VE(w)

With γ = 0.9, TD's error is at most ten times the least, and the bound loosens as γ nears 1; for episodic tasks, such as the cart-pole, a different but related bound holds. What TD gives up in the limit, it often makes up in speed, since its targets vary less than returns. Which method is better depends on the problem, the features, and how long learning runs.

Between the two lies n-step TD, whose semi-gradient form updates the estimate of the state n steps back:

wt+n ≐ wt+n−1 + α[Gt:t+n − v(St, wt+n−1)] ∇v(St, wt+n−1), 0 ≤ t < T

with the n-step return as the eligibility traces note wrote it with weights: n rewards, then γnv(St+n, wt+n−1). The more real rewards a target holds, the less it leans on the estimates, and the closer its fixed point comes to the averages: in the cart-pole, 19.6 steps in the middle ranges for n = 8. 6Summary

The key ideas next to their NumPy equivalents, for a linear estimate. x and x_next are the feature vectors of St and St+1 (all 0 for a terminal state), xs holds the feature vectors of all the states as rows, p_pi[s, s2] is the probability of a step from s to s2 under π, and v_pi, h and mu are indexed by state. In n-step TD, rs holds the n rewards after St, and x_n the feature vector of St+n.

Linear estimate
v(s, w) = wTx(s)
v_hat = w @ x
On-policy distribution
η(s) = h(s) + Σs̄ η(s̄) Σa π(a|s̄)p(s|s̄, a), μ = η/Ση
eye = np.eye(len(h))
eta = h @ np.linalg.inv(eye - p_pi)
mu = eta / eta.sum()
Mean squared value error
VE(w) = Σs μ(s)[vπ(s) − v(s, w)]2
ve = mu @ (v_pi - xs @ w) ** 2
Gradient Monte Carlo
w ← w + α[Gt − v(St, w)]x(St)
w += alpha * (g - w @ x) * x
Semi-gradient TD(0)
w ← w + α[R + γv(S′, w) − v(S, w)]x(S)
g = r + gamma * w @ x_next
w += alpha * (g - w @ x) * x
TD fixed point
wTD = A−1b, with b = E[Rt+1xt] and A = E[xt(xt − γxt+1)T]
w_td = np.linalg.solve(mat_a, b)
n-step semi-gradient TD
w ← w + α[Gt:t+n − v(St, w)]x(St)
g = rs @ gamma ** np.arange(n)
g += gamma ** n * w @ x_n
