The previous note ended with Sarsa on the cliff. Its values count what exploring costs, falls included, so it settles on the route one row up, 9 moves: the best route for an agent that keeps exploring. Once the exploring stops, the edge is two moves shorter and never falls.

Q-learning learns the values of the best route while its agent keeps exploring. This note shows how, and what that costs while it learns. Then come Expected Sarsa, which sits between the two; why the maximum in Q-learning's rule is too optimistic, and how two tables fix it; and a shortcut for when the immediate effect of a move is known.

Throughout this page, routes are drawn in blue ink, and the target of an update, the value an estimate moves toward, in red ink.

1The values of the best behavior

Sarsa learns qπ(s, a), the return to expect after taking action a in state s and then following π, exploring moves and all. The best any policy can do gives the optimal action values:

q*(s, a) = maxπ qπ(s, a)

Knowing q* is enough to act well: in each state, take the action with the largest value. On the cliff, with γ = 1, q* counts moves. From A2, the cell above the start, moving right leaves 6 moves to the goal along the edge, so q*(A2, right) = −6, and moving up costs two more, q*(A2, up) = −8. From B2, a step down into the cliff costs 100, and from the start the best trip still costs 7: q*(B2, down) = −107.

The optimal values are tied together, one step apart, by the Bellman optimality equation. The value of an action is the reward it brings plus the discounted value of acting as well as possible from the state it leads to:

q*(s, a) = E[Rt+1 + γ maxa′ q*(St+1, a′) | St = s, At = a]

Moving right from A2 leads to B2, whose moves up, right, down and left are worth −7, −5, −107 and −7. So q*(A2, right) = −1 + max(−7, −5, −107, −7) = −6.

The agent does not know the rewards and next states in advance, so it cannot solve this equation. Like Sarsa, it keeps an estimate Q(s, a) for every pair and, after each step, moves the estimate of the pair it just tried a fraction α of the way toward a target. The methods on this page differ only in their target.

2The Q-learning update

Q(St, At) ← Q(St, At) + α[Rt+1 + γ maxa Q(St+1, a) − Q(St, At)]

Compare it with Sarsa's. Sarsa's target, Rt+1 + γQ(St+1, At+1), uses the value of the action the agent takes next. Q-learning's uses the best action in the next state, whatever the agent does there. Why this target? It is the inside of the Bellman optimality equation, with its two unknowns replaced by what the agent has. The expectation over rewards and next states becomes the one reward and next state it just observed, and q* becomes the current table Q. Over many steps the randomness of single rewards and next states averages out, as a sample average approaches an expectation, while the table itself improves.

An example with numbers, with α = 0.5. Partway through learning, the table holds Q(A2, right) = −8, and in B2 up −7, right −5, down −60 and left −7. The agent moves right from A2 to B2 and gets −1. The target is −1 + max(−7, −5, −60, −7) = −6, and the estimate moves halfway to it:

Q(A2, right) ← −8 + 0.5(−6 − (−8)) = −7

The target is the same whatever the agent does next in B2, even if its next move is a random step down into the cliff.

The algorithm

The loop is Sarsa's, with one change: the target does not use the next action, so the agent does not have to choose it before updating. It chooses each action at the start of its step, from the table as it stands. For a step size α in (0, 1] and a small ε > 0:

  1. Start with any table Q(s, a), except Q(terminal, ·) = 0.
  2. At the start of each episode, observe the first state S.
  3. Choose an action A in S with a policy derived from Q, such as ε-greedy.
  4. Take A, and observe the reward R and the next state S′.
  5. Update Q(S, A) ← Q(S, A) + α[R + γ maxa Q(S′, a) − Q(S, A)].
  6. Set S ← S′, and go back to step 3 until S is terminal.

The figure runs Q-learning on the cliff with the settings of the Sarsa figure, α = 0.5, γ = 1 and ε = 0.1. Now the agent chooses each move after the last update, and the target uses the best moves of the next cell, outlined in red, whatever the agent does there.

Next goes forward, Back goes back. Keys: → and ←.

When does it work? Q converges to q* with probability 1 as long as every pair keeps being updated, so the policy must never stop trying every action, and the step sizes shrink slowly enough: their sum grows without limit while the sum of their squares stays finite. The first condition is the least any method can ask for, since the value of an action never tried cannot be learned.

3Learning about one policy while following another

The agent behaves ε-greedily, yet its target uses maxa Q(St+1, a), the value of the greedy action in the next state, whatever action it actually takes there. So Q-learning learns the values of the greedy policy, while its experience comes from the ε-greedy one. The policy being learned about is the target policy, and the one that produces the behavior is the behavior policy. When the two differ, the method is off-policy. The behavior policy still matters in one way: it decides which pairs get visited, and so updated.

Sarsa is on-policy: its target uses the action it takes next, so when that action is an exploring move, the target includes what exploring costs. Sarsa learns qπ for the ε-greedy policy it follows, and Q-learning learns q*. A backup diagram shows the difference: what each update looks at, from the pair being updated at the top to what the target is built from at the bottom.

On the cliff, the difference decides the route. Let both methods learn for long enough, with ε = 0.1 and shrinking step sizes. Sarsa settles one row up, as in the previous note. Q-learning's values assume the greedy move from the next step on, so it keeps to the edge, and while it keeps exploring, it sometimes falls in.

Q-learning's table describes the better policy, worth −7 per trip once exploring stops, but Sarsa does better while learning. The gap depends on ε. Below ε ≈ 0.02, a random move down is rare enough that Sarsa keeps to the edge too, and above ε ≈ 0.26 it moves up to the top row. If ε shrinks toward 0 over time, both end up with the optimal policy.

With a purely greedy behavior, ε = 0, the two methods almost coincide: both act greedily, and their targets are equal, since the action Sarsa takes next is the greedy one. The one difference is timing. Sarsa chooses its next action before updating the table, and Q-learning after, so when the next state is the same state, the update can change which action Q-learning then takes. In the Sarsa figure, choosing first cost the agent a second fall from the start.

Many off-policy methods must correct for the difference between the two policies. One-step Q-learning needs no such correction: given the pair it updates, the reward and the next state do not depend on either policy, and the target uses a maximum instead of the action the behavior takes next.

4Expected Sarsa

Q(St, At) ← Q(St, At) + α[Rt+1 + γ Σa π(a|St+1) Q(St+1, a) − Q(St, At)]

Sarsa's target uses the value of the one next action the policy happens to pick, and Q-learning's the value of the best one. Expected Sarsa's target averages the values of all next actions, each weighted by how likely π is to take it. This average, written V(St+1), is the value of the next state that the table implies under π. It is also what Sarsa's target is worth on average, so Expected Sarsa moves every time the way Sarsa moves on average, without the randomness that the choice of At+1 adds. The price is a sum over the actions at every step.

Sarsa's possible targets average 0.925(−6) + 0.05(−8) + 0.025(−108) = −8.65, Expected Sarsa's target. With α = 0.5, starting from Q(A2, right) = −6, Q-learning's update leaves it at −6. Sarsa's leaves it at −6, moves it to −7, or, one time in forty, drops it to −57, depending on the move that happens to come next; Expected Sarsa's always gives about −7.33. With less noise in its updates, Expected Sarsa tolerates a larger step size. On the cliff the moves themselves are certain and all the randomness comes from the policy, so Expected Sarsa can even use α = 1 and replace each estimate by its target, while Sarsa needs a small α to average its random targets.

Expected Sarsa can also learn off-policy: the weights π can come from a target policy other than the behavior. If π is greedy, the average puts all its weight on the best action, and the target is Q-learning's. So Expected Sarsa includes Q-learning as a special case.

5Maximization bias and double learning

Q-learning's target takes the largest of several estimates. The largest of several noisy estimates tends to be too large, even when each of them is right on average. This is maximization bias.

Take a state with six actions that are all worth exactly 0: each pays +1 or −1 with equal chance. Estimate each action by the average of three payments, so an estimate is 1, 1/3, −1/3 or −1. Each estimate is right on average, but the largest of the six is 1 with probability 0.55, 1/3 with probability 0.43, and below 0 less than 2% of the time. On average it is +0.69.

A Q-learning target that ends in such a state gets this optimism added in, and the states that lead there look better than they are. The agent is drawn toward states whose actions are uncertain, for no good reason.

The bias comes from using the same samples twice: to pick the action that looks best, and to say how good it is. Double learning separates the two jobs. It keeps two independent estimates, Q1 and Q2, each learned from its own half of the experience. One picks the action, A* = argmaxa Q1(a), and the other says what it is worth, Q2(A*). The samples behind Q2 played no part in the choice, so E[Q2(A*)] = q(A*), with no bias. In the example, A* is whichever action happened to look best, but its value comes from three fresh payments, which average 0.

Double Q-learning applies this to Q-learning. At each step a coin flip decides which table learns. On heads,

Q1(St, At) ← Q1(St, At) + α[Rt+1 + γQ2(St+1, argmaxa Q1(St+1, a)) − Q1(St, At)]

and on tails the same update with Q1 and Q2 swapped, so that Q2 learns. The two tables play symmetric roles. The behavior can use both, for example ε-greedy with respect to Q1 + Q2. Double learning doubles the memory, but not the work per step, since each step updates only one table. The same idea gives double versions of Sarsa and Expected Sarsa.

6Afterstates

Sometimes the immediate effect of an action is known, and only what follows is uncertain. In a board game you know the position your move leaves, but not your opponent's reply. Then it pays to learn the values of afterstates, the situations right after the agent acts, instead of the values of state–action pairs.

In Nim, two players take turns removing any number of sticks from one pile, and whoever takes the last stick wins. From piles of 3 and 2, taking one stick from the first pile leaves piles of 2 and 2. From piles of 2 and 3, taking one from the second pile leaves the same position.

A table of action values stores two separate numbers here, one for each position and move, and has to learn each on its own. A table of afterstate values stores one number, the value of leaving piles of 2 and 2, and whatever it learns applies to every move that leads there. Piles of 2 and 2 happen to be a winning position to leave: whatever your opponent takes from one pile, you take the same from the other, and you take the last stick.

The learning methods stay the same; only what the table is about changes. Afterstates appear outside games too, whenever an action is defined by its immediate effect, such as loading a parcel onto a particular truck: the loaded truck is known, the traffic on its route is not.
