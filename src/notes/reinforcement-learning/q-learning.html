Picture a robot that has to cross a garden to reach its charger. Nobody gives it a map. All it can do is move, see where it ends up, and receive a reward after each move: −1 per step, so shorter trips are better. From these experiences alone, it has to learn which move is best in each place.

To learn, the robot keeps a table with one number for each place and move: the total reward it expects if it makes that move there and then carries on as well as it can. It also has to keep trying moves that look worse, because that is the only way to find out whether they really are. That creates a problem. If the table records how the robot actually behaves, it describes a robot that now and then steps off the bridge.

Q-learning fills in the table of the best behavior anyway, while the robot keeps experimenting. This note shows how, what that costs while it learns, a close relative called Expected Sarsa, why the maximum in its rule is too optimistic and how two tables fix it, and a shortcut for when the immediate effect of a move is known.

Throughout this page, routes are drawn in blue ink, and the target of an update, the value an estimate moves toward, in red ink.

1What the table holds

At each step t the robot is in a state St and takes an action At. Then it receives a reward Rt+1 and lands in the next state St+1. A trip, called an episode, ends when it reaches a terminal state: the charger, or the pond. What the robot tries to make large is not one reward but the return, the sum of the rewards still to come:

Gt = Rt+1 + γRt+2 + γ2Rt+3 + ⋯

The discount rate γ, between 0 and 1, makes a reward count less the later it comes. In the garden γ = 1, since a step costs the same whenever it happens: crossing the bridge gives a return of −1 − 1 = −2 from the start, and the long way −3.

A policy π says what to do in each state, possibly at random: π(a|s) is the probability of taking action a in state s. The value of an action is the return to expect after taking it and following π from then on:

qπ(s, a) = Eπ[Gt | St = s, At = a]

The best any policy can do gives the optimal action values, q*(s, a) = maxπ qπ(s, a). Knowing q* is enough to act well: in each state, take the action with the largest value. A policy that does that with a table of values is called greedy with respect to it.

The optimal values are tied together, one step apart, by the Bellman optimality equation. The value of an action is the reward it brings plus the discounted value of acting as well as possible from the state it leads to:

q*(s, a) = E[Rt+1 + γ maxa′ q*(St+1, a′) | St = s, At = a]

In the garden, q*(bridge, ahead) = −1, since stepping ahead reaches the charger, and q*(bridge, side) = −20. So q*(start, bridge) = −1 + max(−1, −20) = −2, which beats q*(start, around) = −3.

The robot does not know the rewards and next states in advance, so it cannot solve this equation. Instead it keeps an estimate Q(s, a) for every pair, and after each step it moves the estimate for the pair it just tried a fraction α of the way toward a target, a better guess at the return built from what just happened:

Q(St, At) ← Q(St, At) + α[target − Q(St, At)]

The step size α, between 0 and 1, sets how far each step moves the estimate: α = 1 replaces it with the target, and a small α averages many targets. The methods on this page differ only in their target.

2The Q-learning update

Q(St, At) ← Q(St, At) + α[Rt+1 + γ maxa Q(St+1, a) − Q(St, At)]

Why this target? It is the inside of the Bellman optimality equation, with its two unknowns replaced by what the robot has. The expectation over rewards and next states becomes the one reward and next state it just observed, and q* becomes the current table Q. Over many steps the randomness of single rewards and next states averages out, as a sample average approaches an expectation, while the table itself improves.

This makes Q-learning a temporal-difference (TD) method: it learns from the difference between an estimate now and a better estimate one step later, without waiting for the episode to end. A terminal state has nothing left to earn, so Q(terminal, ·) = 0, and the target of the last step of an episode is just its reward.

An example with numbers. Partway through learning, the table holds Q(start, bridge) = −2.5, Q(bridge, ahead) = −1 and Q(bridge, side) = −10, and α = 0.5. The robot takes the bridge from the start, gets Rt+1 = −1 and lands on the bridge. The target is −1 + max(−1, −10) = −2, and the estimate moves halfway to it:

Q(start, bridge) ← −2.5 + 0.5(−2 − (−2.5)) = −2.25

The algorithm

For a step size α in (0, 1] and a small ε > 0:

  1. Start with any table Q(s, a), except Q(terminal, ·) = 0.
  2. At the start of each episode, observe the first state S.
  3. Choose an action A in S with a policy derived from Q, such as ε-greedy.
  4. Take A, and observe the reward R and the next state S′.
  5. Update Q(S, A) ← Q(S, A) + α[R + γ maxa Q(S′, a) − Q(S, A)].
  6. Set S ← S′, and go back to step 3 until S is terminal.

An ε-greedy policy takes the greedy action, the one with the largest Q(S, a), except that with probability ε it picks an action at random among all of them, the greedy one included. With |𝒜(s)| actions available, the greedy action gets probability 1 − ε + ε/|𝒜(s)| and each other action ε/|𝒜(s)|. On the bridge, with two actions and ε = 0.2, the robot steps ahead with probability 0.9 and to the side with probability 0.1.

When does it work? Q converges to q* with probability 1 as long as every pair keeps being updated, so the policy must never stop trying every action, and the step sizes shrink slowly enough: their sum grows without limit while the sum of their squares stays finite. The first condition is the least any method can ask for, since the value of an action never tried cannot be learned.

3Learning about one policy while following another

The robot behaves ε-greedily, yet its target uses maxa Q(St+1, a), the value of the greedy action in the next state, whatever action it actually takes there. So Q-learning learns the values of the greedy policy, while its experience comes from the ε-greedy one. The policy being learned about is the target policy, and the one that produces the behavior is the behavior policy. When the two differ, the method is off-policy. The behavior policy still matters in one way: it decides which pairs get visited, and so updated.

Sarsa learns about the policy it follows, which makes it on-policy. Its target uses the action it actually takes next:

Q(St, At) ← Q(St, At) + α[Rt+1 + γQ(St+1, At+1) − Q(St, At)]

Its name lists what one update uses: St, At, Rt+1, St+1, At+1. When At+1 is an exploring step, Sarsa's target includes what exploring costs, and Q-learning's never does. So Sarsa learns qπ for the ε-greedy policy it follows, and Q-learning learns q*. A backup diagram shows the difference: what each update looks at, from the pair being updated at the top to what the target is built from at the bottom.

In the garden the difference decides the route. Take ε = 0.2 and let both methods learn for long enough, with shrinking step sizes. For Sarsa, a trip onto the bridge includes a one-in-ten chance of stepping to the side:

qπ(start, bridge) = −1 + 0.9(−1) + 0.1(−20) = −3.9

That is worse than the −3 of the long way, so Sarsa learns to go around. Q-learning's value of the bridge assumes the greedy move from there on, −1 + max(−1, −20) = −2, so it takes the bridge, and while it keeps exploring it sometimes falls in. On the bridge itself both learn the same values, −1 for ahead and −20 for the side step, since the episode ends right after either.

Q-learning's table describes the better policy, worth −2 per trip once exploring stops, but Sarsa does better while learning. The gap depends on ε. Below ε = 2/19 ≈ 0.105, the bridge's value for Sarsa, −2 − 9.5ε, is above −3, and Sarsa takes the bridge too; if ε shrinks toward 0 over time, both end up with the optimal policy.

With a purely greedy behavior, ε = 0, the two methods almost coincide: both act greedily, and their targets are equal, since the action Sarsa takes next is the greedy one. The one difference is timing. Sarsa chooses its next action before updating the table, and Q-learning after, so when the next state is the same state, the update can change which action Q-learning then takes.

Many off-policy methods must correct for the difference between the two policies. One-step Q-learning needs no such correction: given the pair it updates, the reward and the next state do not depend on either policy, and the target uses a maximum instead of the action the behavior takes next.

4Expected Sarsa

Q(St, At) ← Q(St, At) + α[Rt+1 + γ Σa π(a|St+1) Q(St+1, a) − Q(St, At)]

Sarsa's target uses the value of the one next action the policy happens to pick, and Q-learning's the value of the best one. Expected Sarsa's target averages the values of all next actions, each weighted by how likely π is to take it. This average, written V(St+1), is the value of the next state that the table implies under π. It is also what Sarsa's target is worth on average, so Expected Sarsa moves every time the way Sarsa moves on average, without the randomness that the choice of At+1 adds. The price is a sum over the actions at every step.

Sarsa's two possible targets average 0.9(−2) + 0.1(−11) = −2.9, Expected Sarsa's target. So the new estimate is −2.25 after Q-learning's update. After Sarsa's it is −2.25 or −6.75, depending on the action that happens to come next, and after Expected Sarsa's it is always −2.7. With less noise in its updates, Expected Sarsa tolerates a larger step size. In the garden the moves themselves are certain and all the randomness comes from the policy, so Expected Sarsa can even use α = 1 and replace each estimate by its target, while Sarsa needs a small α to average its random targets.

Expected Sarsa can also learn off-policy: the weights π can come from a target policy other than the behavior. If π is greedy, the average puts all its weight on the best action, and the target is Q-learning's. So Expected Sarsa includes Q-learning as a special case.

5Maximization bias and double learning

Q-learning's target takes the largest of several estimates. The largest of several noisy estimates tends to be too large, even when each of them is right on average. This is maximization bias.

Take a state with six actions that are all worth exactly 0: each pays +1 or −1 with equal chance. Estimate each action by the average of three payments, so an estimate is 1, 1/3, −1/3 or −1. Each estimate is right on average, but the largest of the six is 1 with probability 0.55, 1/3 with probability 0.43, and below 0 less than 2% of the time. On average it is +0.69.

A Q-learning target that ends in such a state gets this optimism added in, and the states that lead there look better than they are. The agent is drawn toward states whose actions are uncertain, for no good reason.

The bias comes from using the same samples twice: to pick the action that looks best, and to say how good it is. Double learning separates the two jobs. It keeps two independent estimates, Q1 and Q2, each learned from its own half of the experience. One picks the action, A* = argmaxa Q1(a), and the other says what it is worth, Q2(A*). The samples behind Q2 played no part in the choice, so E[Q2(A*)] = q(A*), with no bias. In the example, A* is whichever action happened to look best, but its value comes from three fresh payments, which average 0.

Double Q-learning applies this to Q-learning. At each step a coin flip decides which table learns. On heads,

Q1(St, At) ← Q1(St, At) + α[Rt+1 + γQ2(St+1, argmaxa Q1(St+1, a)) − Q1(St, At)]

and on tails the same update with Q1 and Q2 swapped, so that Q2 learns. The two tables play symmetric roles. The behavior can use both, for example ε-greedy with respect to Q1 + Q2. Double learning doubles the memory, but not the work per step, since each step updates only one table. The same idea gives double versions of Sarsa and Expected Sarsa.

6Afterstates

Sometimes the immediate effect of an action is known, and only what follows is uncertain. In a board game you know the position your move leaves, but not your opponent's reply. Then it pays to learn the values of afterstates, the situations right after the agent acts, instead of the values of state–action pairs.

In Nim, two players take turns removing any number of sticks from one pile, and whoever takes the last stick wins. From piles of 3 and 2, taking one stick from the first pile leaves piles of 2 and 2. From piles of 2 and 3, taking one from the second pile leaves the same position.

A table of action values stores two separate numbers here, one for each position and move, and has to learn each on its own. A table of afterstate values stores one number, the value of leaving piles of 2 and 2, and whatever it learns applies to every move that leads there. Piles of 2 and 2 happen to be a winning position to leave: whatever your opponent takes from one pile, you take the same from the other, and you take the last stick.

The learning methods stay the same; only what the table is about changes. Afterstates appear outside games too, whenever an action is defined by its immediate effect, such as loading a parcel onto a particular truck: the loaded truck is known, the traffic on its route is not.
